# persian-rtl

پلاگینی برای Claude Code که **همه‌ی پیام‌های کاربر و دستیار** و هر ردیف دیگری که دست‌کم یک نویسه‌ی فارسی دارد (خروجی دستورهای `/`، فراخوانی و نتیجه‌ی ابزارها) را راست‌چین می‌کند و متن فارسی و انگلیسی مخلوط را در ترمینال درست، یعنی از راست به چپ، نشان می‌دهد.

ترمینال‌هایی مثل Konsole خودشان bidi را درست انجام نمی‌دهند: جمله‌ی فارسی چپ‌چین می‌شود، نقطه‌ی پایانی به ابتدای جمله می‌پرد و کلمات انگلیسی وسط جمله جابه‌جا می‌شوند. این پلاگین پیش از رسیدن متن به ترمینال، چیدمان را خودش محاسبه می‌کند.

> **وضعیت:** آزمایش‌شده در Konsole با Claude Code نسخه‌ی 2.1.289. در ترمینال‌های دیگر ممکن است نتیجه فرق کند (بخش «محدودیت‌ها» را ببینید).

## نصب

### نصب دائمی (بدون هیچ سوئیچی در اجراهای بعدی)

پلاگین یک بار نصب می‌شود و از آن به بعد در هر اجرای `claude` فعال است:

```sh
claude plugin marketplace add /مسیر/به/این/مخزن      # یا نشانی GitHub مخزن
claude plugin install persian-rtl@rtlclaudecode
```

اگر Claude Code از قبل باز است، داخل آن `/reload-plugins` را بزنید. برای خاموش کردن: `claude plugin disable persian-rtl`.

### اجرای موقت (فقط برای همان اجرا)

```sh
claude --plugin-dir /مسیر/به/این/مخزن
```

در این حالت باید هر بار این سوئیچ را بدهید.

## حذف

هر کدام از این‌ها را متناسب با روش نصبتان انجام دهید. بعد از آن `/reload-plugins` را بزنید یا Claude Code را دوباره باز کنید.

| وضعیت | دستور |
| --- | --- |
| فقط خاموش کردن، بدون حذف (بعداً با `claude plugin enable persian-rtl` برمی‌گردد) | `claude plugin disable persian-rtl` |
| حذف پلاگین نصب‌شده | `claude plugin uninstall persian-rtl` |
| حذف marketplace محلی (بعد از حذف پلاگین) | `claude plugin marketplace remove rtlclaudecode` |
| اجرای موقت با `--plugin-dir` | کاری لازم نیست؛ فقط دیگر آن سوئیچ را ندهید |

اگر پلاگین را با `--scope project` یا `--scope local` نصب کرده‌اید، دستور حذف را هم با همان `--scope` بزنید. حذف پلاگین به فایل‌های مخزن دست نمی‌زند؛ پوشه‌ی مخزن را اگر لازم نیست خودتان پاک کنید.

## چه کاری می‌کند

| ورودی | نتیجه |
| --- | --- |
| پاسخ دستیار و پیام کاربر (فارسی یا انگلیسی) | کنار راست چیده می‌شود |
| نقطه، ویرگول فارسی، گیومه، پرانتز | در سمت درست جمله می‌نشینند (پرانتز و «» آینه می‌شوند) |
| کلمات انگلیسی و `code` میان جمله‌ی فارسی | ترتیب خواندن درست می‌ماند |
| لیست نقطه‌ای و شماره‌دار، نقل‌قول `>`، عنوان `#` | نشانگر در لبه‌ی راست است و خط‌های بعدی زیر متن آویزان می‌شوند |
| `**bold**`، `*italic*`، `` `code` `` | پررنگ، مایل و فیروزه‌ای رندر می‌شوند |
| بلوک کد و جدول | بدون تغییر و چپ‌چین (با رندر خود Claude Code) |
| خروجی دستورهای `/` (`CommandOutput`) و خط‌های وضعیت زیر لوگو (`InfoNotice`) | اگر دست‌کم یک نویسه‌ی فارسی داشته باشند، مثل پیام‌ها راست‌چین می‌شوند |
| ردیف فراخوانی ابزار (`ToolUse`، مثل `Bash(...)`) | اگر ورودی ابزار دست‌کم یک نویسه‌ی فارسی داشته باشد، یک خط `ابزار(آرگومان اصلی)` با `●` در لبه‌ی راست جای ردیف اصلی می‌نشیند |
| نتیجه‌ی ابزار (`ToolResult`): Bash، Read، Grep و هر ابزاری که متنش در `stdout`، `content`، `file.content`، `text`، `result` یا `output` باشد | اگر دست‌کم یک نویسه‌ی فارسی داشته باشد، خط‌به‌خط راست‌چین می‌شود (حداکثر ۶۰ خط، بدون تجزیه‌ی مارک‌داون، stderr قرمز) |

## محدودیت‌ها

- **مارک‌داون ساده‌شده:** فقط `**bold**`، `*italic*`، `` `code` ``، عنوان، لیست و نقل‌قول پشتیبانی می‌شوند. لینک‌ها فقط به متن برچسبشان تبدیل می‌شوند. بلوک کد و جدول با رندر خود Claude Code نمایش داده می‌شوند.
- **نشانگرهای ابتدای پیام:** `●` ابتدای پاسخ و `❯` پیام کاربر برای پیام‌های راست‌چین‌شده دیده نمی‌شود.
- **خروجی ابزارهای ساختاریافته:** نتیجه‌ی ابزارهایی که متنشان در یکی از فیلدهای بالا نیست (مثل diff ویرایش `Edit` و `Write`) و ردیف‌های چندبخشی (`ToolGroup` مثل `Ran 2 shell commands`) را موتور خودش می‌کشد و راست‌چین نمی‌شوند.
- **دیالوگ پرسش (`AskUserQuestion`):** راست‌چین نمی‌شود، چون تعاملی است و جایگزین کردنش گزینه‌های انتخابی را از کار می‌اندازد.
- **کادر ورودی (جایی که تایپ می‌کنید):** راست‌چین نمی‌شود. پلاگین‌ها فقط می‌توانند متن پیش‌نویس را بخوانند و تغییر بدهند یا روی نویسه‌هایش رنگ بزنند، نه جای آن را. چیدمان آن کار خود Claude Code است. بعد از ارسال، پیام در `UserMessage` راست‌چین می‌شود.
- **نوار پایین و خطوط وضعیت** (`Spinner`، `TurnDuration`، `PromptHint`، `SessionMode`): این‌ها متن ثابت انگلیسی هستند و چیزی برای راست‌چین کردن ندارند.
- **فونت:** پلاگین فونت ترمینال را تغییر نمی‌دهد و نمی‌تواند؛ فونت را خود ترمینال انتخاب می‌کند (در Konsole: Settings ← Edit Current Profile ← Appearance ← Font). ترمینال به فونت **هم‌عرض** نیاز دارد، پس فونت‌های متناسب مثل Vazirmatn مناسب نیستند و حروف لاتین و فاصله‌ها را بههم می‌ریزند. فونت هم‌عرضِ فارسی [Vazir Code](https://github.com/rastikerdar/vazir-code-font) این مشکل را ندارد: از میان نسخه‌هایش `Vazir Code Hack` حروف لاتین فونت Hack را دارد و برای کد مناسب است، پسوند `FD` ارقام فارسی را به‌جای لاتین می‌گذارد، `WOL` لیگاچر را حذف می‌کند و `Extra Height` فاصله‌ی خطوط را بیشتر می‌کند. چیدمان این پلاگین هر نویسه را یک خانه حساب می‌کند و با فونت هم‌عرض سازگار است. تغییر فونت فقط ظاهر را عوض می‌کند و ترتیب راست‌به‌چپ را که این پلاگین حساب می‌کند تغییر نمی‌دهد.
- **عرض خط:** از عرض ترمینال منهای ۶ ستون استفاده می‌شود. اگر ترمینال عرضش را اعلام نکند ۸۰ ستون فرض می‌شود.
- **نویسه‌ی خالی U+2800:** جلوی کلمه‌ی لاتینِ شروع‌شده با رقم (مثل `6.png`) و جلوی شماره‌ی لیست گذاشته می‌شود. اگر قلم ترمینال این نویسه را خالی نکشد، یک خانه‌ی غیرخالی دیده می‌شود.
- **ترمینال‌های دیگر:** چیدمان برای رفتار Konsole تنظیم شده است (bidi روی کل ردیف با جهت پایه‌ی چپ‌به‌راست). در ترمینال‌هایی که bidi را انجام نمی‌دهند یا به شکل دیگری انجام می‌دهند ممکن است ترتیب کلمات برعکس دیده شود.
- **فارسی و انگلیسی یکسان رفتار می‌کنند:** پیام کاملاً انگلیسی هم راست‌چین می‌شود. اگر نمی‌خواهید، `hooks/register.tsx` را ویرایش کنید (بخش «توسعه»).

## چرا این‌طور کار می‌کند

آزمایش در Konsole این‌ها را نشان داد:

1. Konsole الگوریتم bidi یونیکد را روی **کل ردیف** با جهت پایه‌ی **چپ‌به‌راست** اجرا می‌کند. پس هر گروه حروف فارسی را خودش وارونه می‌چیند، ولی نقطه‌ی پایان جمله را سمت راست می‌گذارد.
2. نویسه‌های کنترلی بدون عرض (`RLM`، `LRM`) به خانه‌ی قبلی می‌چسبند و نادیده گرفته می‌شوند. `RLE`، `RLI`، `PDF`، `PDI` و `ALM` به شکل `�` کشیده می‌شوند. پس راه «جهت را با نویسه‌ی کنترلی اعلام کن» کار نمی‌کند.
3. رقم بعد از حروف فارسی «عدد عربی» می‌شود و به گروه فارسی می‌چسبد.

بنابراین `hooks/bidi.ts` متن را این‌طور می‌چیند:

1. متن به کلمه‌ها شکسته می‌شود و هر نویسه استایل خودش (`plain`، `bold`، `italic`، `code`) را دارد. استایل روی ترتیب اثر ندارد.
2. کلمه‌ها در ردیف‌هایی به عرض ترمینال شکسته می‌شوند. موتور خودش خطی نمی‌شکند.
3. در هر ردیف، کلمه‌های پشت‌سرهم با زبان یکسان یک «گروه» می‌شوند. فارسی یعنی دست‌کم یک حرف یا رقم فارسی. لاتین یعنی بقیه‌ی کلمه‌های حرف‌دار. کلمه‌ی بدون حرف (مثل `-` یا عدد) به گروه قبلی می‌چسبد.
4. گروه‌ها **برعکس** پشت هم قرار می‌گیرند. داخل هر گروه ترتیب منطقی می‌ماند و Konsole حروف گروه فارسی را خودش وارونه می‌کند.
5. علامت پایانی هر گروه (`.` `،` `؟` `)` ...) به **ابتدای** گروه و علامت آغازین (`(` `«` ...) به **انتهای** آن می‌رود. براکت‌ها آینه می‌شوند.
6. نشانگر لیست به انتهای ردیف (لبه‌ی راست) می‌رود.
7. هر ردیف در یک `Box` با `alignSelf="flex-end"` رندر می‌شود و استایل نویسه‌ها به `Text` تبدیل می‌شود.

## ساختار مخزن

```
.claude-plugin/plugin.json        مانیفست پلاگین
.claude-plugin/marketplace.json   مانیفست marketplace (برای نصب دائمی)
hooks/hooks.json                  ماژول‌های پلاگین را معرفی می‌کند
hooks/register.tsx                هوک ui.render برای AssistantMessage، UserMessage، CommandOutput، InfoNotice، ToolUse و ToolResult، رندر JSX
hooks/bidi.ts                     تجزیه‌ی مارک‌داون، شکستن خط و چیدمان راست‌به‌چپ (بدون وابستگی به UI)
hooks/register.test.ts            آزمون‌ها
```

## توسعه

```sh
claude plugin validate .          # اعتبارسنجی مانیفست و هوک‌ها
claude plugin test .              # اجرای آزمون‌ها
claude --plugin-dir .             # اجرای Claude Code با نسخه‌ی در حال ویرایش
```

- برای راست‌چین کردن فقط پیام‌های فارسی، ابتدای هوک `ui.render` در `hooks/register.tsx` را این‌طور تغییر دهید تا پیام‌های غیرفارسی دست‌نخورده بمانند:

  ```ts
  const persian = [...text].filter(c => /[\u0600-\u06FF]/.test(c) && /\p{L}/u.test(c)).length
  const letters = [...text].filter(c => /\p{L}/u.test(c)).length

  if (letters === 0 || persian / letters <= 0.5) {
    return next(e)
  }
  ```

- `hooks/bidi.ts` عمداً به API پلاگین وابسته نیست تا با `claude plugin test` آزمون شود. هر تغییری در قواعد چیدمان باید یک آزمون داشته باشد.
- نتیجه‌ی نهایی را فقط می‌شود در خود ترمینال دید. آزمون‌ها ترتیب رشته‌ی خروجی را بررسی می‌کنند، نه رنگ‌آمیزی ترمینال را.
